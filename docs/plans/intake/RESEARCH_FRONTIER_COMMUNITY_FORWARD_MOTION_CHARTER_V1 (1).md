# 0. Executive diagnosis

The project does not primarily suffer from a shortage of ideas.

It already has:

- a mathematical claims ledger;
- epistemic-discipline rules;
- a negative-results archive;
- an open-questions register;
- source-verification procedures;
- exact and heuristic computational tools;
- record-hunting pipelines;
- code-audit practices;
- educational visualizations;
- AI-agent rules;
- long-term vision documents.

The next missing layer is an **operating system for sustained progress**.

The project needs a repeatable mechanism that turns:

```text
literature
→ precise question
→ bounded task
→ artifact
→ independent verification
→ claim or negative result
→ lesson
→ public challenge
→ new contributor
```

This charter proposes that mechanism.

The central principle is:

> **The project must always have several legitimate ways to advance.**

If the main conjecture is blocked, progress may still consist of:

- proving a neighboring theorem;
- producing a trusted finite certificate;
- rejecting a plausible conjecture;
- identifying an algorithmic hardness boundary;
- formalizing one correctness lemma;
- improving a verifier;
- reproducing another researcher’s result;
- creating a teachable research module;
- building a benchmark for research AI;
- publishing a reusable dataset;
- onboarding and mentoring a new contributor.

A project that recognizes only “solve the conjecture” as progress will eventually stall.

A project with a diversified research portfolio can continue indefinitely while preserving scientific discipline.

# 3. The forward-motion cycle

Every serious project item should move through this cycle:

```text
READ
Understand the strongest available source.

FORMALIZE
State the object, scope, quantifiers, and exact claim.

CHALLENGE
Search for small counterexamples and boundary failures.

COMPUTE
Run a bounded, manifested experiment.

VERIFY
Use an independent code path, proof checker, or external reviewer.

INTERPRET
State exactly what the result proves and does not prove.

TEACH
Turn the result or failure into an understandable lesson.

INVITE
Publish a bounded replication or extension task.

ARCHIVE
Preserve artifacts, checksums, provenance, and status.

REVIEW
Decide whether to continue, reformulate, pause, or close the line.
```

No research line should remain indefinitely at:

```text
interesting idea
```

It should either become executable or be archived as undeveloped.

# 5. Portfolio allocation

A suggested default allocation of project attention:

```text
30% main mathematical research
20% exact finite results and certificates
15% algorithms and software correctness
10% literature and formalization
10% education
10% community and replication
5% AI evaluation infrastructure
```

This is not a funding formula.

It is a protection against spending all available time on one long-running record hunt or one speculative route.

## 5.1 Work-in-progress limit

At any one time, maintain at most:

```text
3 active mathematical research lines
2 active infrastructure projects
2 active educational/community pilots
```

Everything else remains in the backlog.

## 5.2 Quarterly review

Every three months, each active line receives one decision:

```text
CONTINUE
NARROW
MERGE
PAUSE
REJECT
PROMOTE
PUBLISH
```

The decision and reasoning are archived.

# 7. Missing guiding document 2: Proof-Carrying Computation Standard

Create:

```text
docs/standards/PROOF_CARRYING_COMPUTATION_STANDARD.md
```

## 7.1 Goal

A large computation should produce more than:

```text
the program printed EXHAUSTED
```

It should produce an artifact that a much smaller trusted checker can validate.

## 7.2 Certificate families

### Record certificate

Contains:

- exact word;
- class;
- length;
- SHA-256;
- independent verifier outputs;
- software versions;
- provenance.

### Partition exhaustion certificate

Contains:

- root seed;
- target;
- complete prefix partition;
- task identifiers;
- task completion records;
- hashes of inputs and outputs;
- no missing or duplicated subtrees;
- stop status for every task.

### SAT certificate

Where a finite subproblem is encoded as SAT:

- CNF checksum;
- solver output;
- DRAT/LRAT proof when unsatisfiable;
- independently run proof checker.

### Graph certificate

Contains:

- graph definition;
- vertex and edge checksum;
- SCC decomposition;
- claimed property;
- independent graph checker.

### Cut-and-certify certificate

Contains:

- child certificates;
- complete crossing-obligation ledger;
- independent join verification.

## 7.3 Trusted-kernel principle

The search program may be large and optimized.

The certificate checker should be:

- small;
- deterministic;
- documented;
- independently tested;
- preferably reimplemented in another language.

# 15. New research program 1: Finite-type approximation tower

This extends existing bounded-\(K\) work into a coherent symbolic-dynamics program.

## 15.1 Definition

For each \(k\ge2\), define \(X_k\) as the set of bi-infinite ternary sequences avoiding Abelian squares with:

\[
2 \le K \le k.
\]

Each \(X_k\) is describable using a finite set of forbidden factors and can be represented as a shift of finite type at a sufficiently large memory.

The sequence is nested:

\[
X_{k+1}\subseteq X_k.
\]

## 15.2 Questions

- Is \(X_k\) nonempty?
- What is its topological entropy?
- What recurrent SCCs remain?
- What letter-frequency vectors occur?
- How many right-special factors remain?
- What is the shortest periodic point?
- What synchronization words exist?
- How does the core change from \(k\) to \(k+1\)?

## 15.3 Proposed project conjectures

These are original project hypotheses, not literature claims.

### COW-H1 — Core-forcing trend

> The proportion of recurrent states with out-degree one increases along a substantial subsequence of \(k\).

This is finitely testable and may be false.

### COW-H2 — Minimum-period divergence

> The minimum period of a periodic point in \(X_k\) tends to infinity with \(k\).

A qualitative divergence is expected from periodic obstruction reasoning, but the useful research question is the quantitative growth rate.

### COW-H3 — Entropy-drop recurrence

> The entropy values \(h(X_k)\) decrease strictly for infinitely many \(k\).

Test finite levels; do not infer the limit from a short trend.

### COW-H4 — Frequency-polytope contraction

> The set of letter-frequency vectors realized by recurrent components contracts in a structurally nontrivial way as \(k\) grows.

## 15.4 First experiment

For manageable \(k\):

- construct the exact automaton;
- remove transient states;
- compute SCCs;
- compute spectral radii;
- enumerate cycle frequency vectors;
- archive graph certificates;
- compare independent implementations.

## 15.5 Kill condition

Pause if state explosion prevents progress before producing new bounded results and no quotient or symmetry reduction succeeds.

# 16. New research program 2: Minimal forbidden obstruction basis

## 16.1 Definition

A word \(u\) is a minimal forbidden factor for a language \(L\) when:

```text
u not in L
every proper factor of u belongs to L
```

Study this for:

- AA2F finite-factor languages;
- AA2FR;
- bounded-\(K\) approximations;
- D40-related languages.

## 16.2 Why valuable

Minimal obstructions can serve as:

- canonical counterexamples;
- teaching examples;
- regression tests;
- pruning motifs;
- conjecture generators;
- language fingerprints.

## 16.3 Proposed project conjectures

### COW-H5 — Single-witness dominance

> A large majority of minimal forbidden AA2F factors have one canonical first Abelian-square witness spanning the whole word.

This is empirical and must be tested by exact enumeration.

### COW-H6 — Obstruction-growth law

> Canonical minimal forbidden factors have an asymptotic growth rate distinct from the valid-factor growth rate.

### COW-H7 — FORBID4 obstruction families

> The six FORBID4 patterns remove a small number of symmetry-related infinite obstruction families rather than six isolated local accidents.

## 16.4 First experiment

For lengths up to a feasible bound:

- enumerate canonical valid and invalid words;
- detect minimal forbidden factors;
- quotient by alphabet permutations and reversal;
- record first witness and witness count;
- calculate context-extension behavior.

## 16.5 Educational output

Create a public obstruction atlas:

```text
smallest example
symmetry orbit
why forbidden
minimality certificate
common misconception
```

# 17. New research program 3: Equivalence-design lattice

The project currently studies Abelian equivalence and related local constraints.

Generalize the design space.

## 17.1 Equivalence features

A block equivalence may use selected statistics:

- letter counts;
- selected bigram counts;
- weighted letter sums;
- modular counts;
- bounded-length subword counts;
- first/last symbol;
- symmetry-invariant functionals.

## 17.2 Central question

> What is the smallest amount of local statistical information that changes avoidability behavior?

This connects:

- Abelian equivalence;
- additive equivalence;
- \(k\)-Abelian equivalence;
- partial bigram equivalence;
- FORBID4 side constraints.

## 17.3 Proposed project conjectures

### COW-H8 — Small orbit threshold

> Up to alphabet symmetry, a small orbit of selected bigram constraints is sufficient to change the infinite avoidability threshold.

### COW-H9 — Minimal antichain structure

> Minimal constraint sets that alter avoidability form a small number of canonical antichain types under symmetry and inclusion.

## 17.4 First experiment

- define a finite constraint lattice;
- canonicalize under \(S_3\);
- run bounded exact searches;
- classify minimal changes;
- preserve all counterexamples.

## 17.5 Caution

A bounded survival trend is not an infinite avoidability result.

# 21. New research program 7: Algorithmic tractability boundary

General Abelian-square detection has known conditional hardness connections.

Rather than seeking one universal fast algorithm, classify restricted regimes.

## 21.1 Candidate regimes

- bounded \(K\);
- bounded discrepancy;
- morphic inputs;
- automatic inputs;
- paths in a fixed D40 graph;
- low-entropy components;
- bounded number of right-special factors;
- run-length restricted words;
- fixed block libraries;
- incremental append-only verification.

## 21.2 Questions

- Which restrictions permit linear-time verification?
- Which admit finite-state checking?
- Which preserve hardness?
- What is the exact cost per append?
- Can preprocessing improve repeated queries?
- What certificates can be emitted?

## 21.3 Proposed hypothesis

### COW-H13 — D40 average-case acceleration

> The structural restrictions of long D40-compatible paths permit a measurably smaller average set of relevant \(K\)-checks than unrestricted AA2FR paths, while exact fallback remains available.

This must be measured without claiming worst-case improvement.

# 22. New research program 8: No-go theorems for local memory

The project is exploring local dictionaries, boundary signatures, and cut certificates.

It should also search for impossibility results.

## 22.1 General form

For a proposed state summary \(S_r(w)\) depending on only the last \(r\) symbols or selected local statistics, find:

```text
prefixes x and y
with S_r(x) = S_r(y)

and a continuation z
such that xz is valid but yz is invalid
```

## 22.2 Proposed hypothesis

### COW-H14 — Unbounded future-relevant memory

> No fixed-radius suffix state is sufficient to determine all future AA2F-valid continuations.

A precise theorem would require exact definitions and proof.

## 22.3 Value

A no-go theorem can redirect effort from impossible finite-state models toward:

- growing summaries;
- certificates;
- restricted languages;
- approximate ordering heuristics.

# 27. How to attract researchers

Researchers join when the project offers:

1. a precise question;
2. a credible path to a result;
3. trustworthy artifacts;
4. visible open problems;
5. low ambiguity about credit;
6. responsive collaborators;
7. publication potential.

## 27.1 Researcher-facing packet

Every serious research question should provide:

- formal statement;
- literature status;
- project status;
- current data;
- source files;
- exact commands;
- negative results;
- what has already failed;
- next smallest experiment;
- publication-level significance;
- contact person;
- authorship expectations.

## 27.2 Do not recruit with

```text
Help us solve Mäkelä's conjecture.
```

Recruit with:

```text
Can you independently certify this finite exhaustion?
Can you classify this symmetry quotient?
Can you prove or refute this boundary-state lemma?
Can you reproduce this template-sieve result?
```

# 35. What keeps a project moving forever

Use a **progress substitution rule**.

When a research line is blocked, choose one of:

```text
decrease the scope
change the representation
find the smallest counterexample
formalize one lemma
build an independent checker
reproduce a source
measure the bottleneck
teach the concept
invite an external challenge
archive the negative result
```

A blocked proof does not imply a blocked project.

## 35.1 Weekly question

Every week ask:

> What is the smallest independently checkable artifact we can create next?

## 35.2 Monthly question

Every month ask:

> Which assumption is currently consuming the most effort without being tested directly?

## 35.3 Quarterly question

Every quarter ask:

> Which research line would we stop if it belonged to someone else?

This protects against attachment to sunk costs.

# 37. The two-way teaching rule

Every advanced research artifact should generate one educational artifact.

```text

→ lesson on state-machine correctness

→ lesson on local versus global constraints

finite record
→ lesson on finite versus infinite claims

→ counterexample workshop

certificate
→ lesson on trusted computing
```

Every educational activity should point back to current research evidence.

This prevents the Learning Lab from becoming detached from the science.

# 44. Final recommendation

The most valuable next step is not another large feature.

It is to make the project **legible and joinable**.

A visitor should be able to answer within five minutes:

```text
What is known?
What is open?
What can I do?
How will my contribution be checked?
How will I receive credit?
What would count as a meaningful result?
```

A contributor should be able to create a useful artifact within one day.

A student should be able to see a path from first example to real research.

A teacher should be able to run one lesson without understanding the entire repository.

A researcher should be able to identify a publication-quality bounded question.

An AI agent should be able to retrieve the current evidence state and be penalized for unsupported claims.

The durable project formula is:

> **Precise questions + small trusted artifacts + visible mentorship + independent verification + honest publication.**

And the permanent forward-motion rule is:

> **When proof is blocked, produce the next independently checkable object.**
