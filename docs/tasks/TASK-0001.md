## 0. Why this task and not a research experiment

The bootstrap instruction requires stating this explicitly when the highest-priority
item is not an experiment. It is not, and here is the selection against the seven
criteria.

| Criterion | TASK-0001 (D40 provenance) | Cut-and-Certify E1 |
|---|---|---|
| **Authority** | Owner directed a bounded provenance task before any D40-dependent campaign | Nearest-executable *among Wave 3 plans*; explicitly does **not** displace `NEXT_STEP.md` |
| **Safety / rights dependency** | **It is the rights item.** The file is tracked in a public repository with unresolved provenance | None |
| **Reversibility** | Fully reversible — adds files, changes nothing, deletes nothing | Fully reversible |
| **Boundedness** | One file, one inventory, one decision record | One detector, one exhaustive comparison |
| **Verification value** | Moderate — produces preserved, checkable evidence | **High** — produces a Layer-4 verifier candidate |
| **Blocking effect** | **Highest in the programme.** Gates the entire D40 line | **Zero.** Nothing waits on E1 |
| **Fit with the bootstrap allocation** | Squarely in the 60% safety bucket (OD-9) | The 30% research bucket |

E1 scores higher on verification value and is genuinely excellent work. It loses on
the two criteria that decide ordering: **blocking effect** and **time sensitivity**.
Nothing degrades if E1 waits a week. The dataset is publicly tracked *now*, and the
owner direction requires its metadata preserved **before** tracking changes — so
every day it stays untraced is a day the evidence could be disturbed by unrelated
work in a shared worktree.

E1 is `NEXT` in `ROADMAP.md` §4 and should follow immediately.

## 6. Implementation steps

### Step 0 — Capture the baseline working-tree state

Before touching anything, capture the **complete** output of:

```bash
git status --short
```

Preserve it **verbatim** as an appendix in
`research/dictionaries/D40-0001/PROVENANCE.md`.

The repository already contains unrelated untracked files — six
`checkpoint_worker_*.json`, seven `record_word_*.txt` / `progressive_log.txt`, and
several `scratch/` files at the time of writing. **These are not part of this task.**
Do not modify, delete, add to, or triage any pre-existing untracked file. They are
process question P-2 and belong to a different decision.

The baseline exists so completion can be verified as a **difference**, not as an
absolute state.

### Step 1 — Preserve, before anything else

Record, without modifying the file:

```text
exact filename
SHA-256
size in bytes
line count
first and last line (verbatim)
git status: tracked / untracked
commit that added it, and any commit that modified it
current working-tree mtime
```

Write to `research/dictionaries/D40-0001/source-metadata.json` using the manifest
field set from `DICTIONARY_BACKTRACKER_RESEARCH_PLAN.md` §5.1, with unknown fields
recorded as `null` and **not** guessed.

### Step 2 — Structural facts (read-only, no compilation)

```text
number of lines of length exactly 40
number of lines of other lengths
alphabet check: any character outside {a,b,c}
```

**Do not** compile the dictionary, expand symmetries, verify AA2FR membership, or run
any search. Those are D40 work, blocked by OD-2.

### Step 3 — Trace provenance

Search the repository's own record for the file's origin: commit messages, `NEXT_STEP.md`
handoffs, `MATH_CLAIMS.md` rows referencing record words or Keränen data,
`.gitignore` comments, `datasets/README.md`.

Record for each lead: what was found, where, and **how confident** the conclusion is.

Per `AGENTS.md` rule 4, *"I am not sure where this came from"* is an acceptable and
desirable finding when true. **Do not construct a provenance story to fill the gap.**

### Step 4 — Build the dependency graph

Enumerate every place that consumes or names this file: intake plans, the Java guide's
invocations, `scratch/` code, and any script default path. Record file and line.

### Step 5 — Write the findings

`docs/program/OD-2-PROVENANCE-FINDINGS.md` states, as a table:

```text
what is known
what is not known
what would resolve the remaining gap
which of the five OD-2 steps becomes available under each outcome
```

Frame outcomes as options for the owner. **Do not select one.**
